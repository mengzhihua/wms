# 仓型深度开发计划

对标京东快消仓、大件仓和 VMI 仓，在现有 WMS 上按仓型加深，而不是另起三套系统。

库存账继续以仓库、库位、货主、物料、批次为粒度，变动仍走 `InventoryService`。仓型决定上架、分配、补货、波次、容器和物权怎么走。现有仓库默认 `GENERAL`，行为与现在一致。

核对范围是本仓库 2026-10 的代码：`Warehouse`、`Location`、`Item`、`Inventory`、`InventoryService`、`AsnService`、`ReplenishService`、`WaveStrategy` 和 `data.sql` 里的八条波次策略。

## 结论

| 仓型 | 已闭环 | 半成品 | 未做 | 判断 |
| --- | ---: | ---: | ---: | --- |
| 快消 | 6 | 2 | 2 | 主链路已经像小件电商仓，差的是策略没用上现有字段 |
| 大件 | 2 | 2 | 6 | 序列号和质检能用，作业单位仍是件，没有托盘、月台、送装 |
| VMI | 3 | 0 | 7 | 多货主库存和采购收货回传 SRM 已在，没有寄售物权和消耗过账 |

每类 10 项，见文末清单。半成品指字段或邻接流程已经在库里，策略没有读它们。

建议顺序：先让跨仓调入的库存能够被分配，再加仓型开关，然后让承重、容积、拣货顺序生效，接着做快消策略包。容器（LPN）放在大件和 VMI 之前。月台、整托、物权协议都依赖容器和仓型，不提前做。

## 现有底座

这些能力三种仓型都继续用：

- 库存引擎：收货、上架、分配、拣货、发运、移库、冻结、调整、盘点锁库，流水统一记账。
- 分配：`InventoryService.allocate` 先效期后收货日，只从 `STORAGE` / `PICKING` 出，允许部分分配。
- 波次：`data.sql` 已预置单品单件、一品两件、一品波次、两品两件、一单一件多品、单区、混合、尾单。策略可按货主、承运商、库区分组，可预览。
- 越库：ASN 绑出库单，收货直接进发货暂存。
- 拣货位 Min/Max 补货，以及跨仓调拨先入收货暂存、确认后进拣货位。
- 质检冻结、序列号收发、箱型推荐和包材扣减、盘点计划锁库、ABC、按件计件。
- 货主维度库存；采购入库收完后可回传 SRM；控制塔可按单分配、按仓补货。

`wms_warehouse` 今天只有编码、名称、地址、联系人和是否审核。没有仓型。三种业务因此走同一套上架和分配。

## 必须先修的账

`allocate` 只取 `refNo` 为空的库存。上架确认把目标库存的引用清成空字符串（`AsnService` 调用 `move(..., "")`），所以正常收货上架后可以分配。

跨仓调拨不是这条路径：

1. `ReplenishService.transfer` 把货收入目标仓暂存位时，`refNo` 写成补货任务号。
2. `confirmTransfer` 再移到拣货位时沿用源行的 `refNo`，没有清掉。
3. 货已经在拣货位，分配仍把它排除。

仓内补货的来源若是上架后的空引用库存，移库后仍为空，不受影响。

切片 0 只改调拨确认：目标库存引用写成空字符串，并补一条「调拨确认后可以分配」的测试。这一刀不引入仓型。

## 快消仓

京东快消（小件电商）的作业口径：订单按结构拆开（单品单件、单品多件、多品），爆品固定拣货位，存储位按箱补到拣货位，波次按承运商截单释放，复核和包材按件计。人效看行和件，库存看效期。

本仓库已经覆盖订单结构波次、FEFO、箱型包材、缺货、拣货位 Min/Max、越库。

还没接上的两处半成品：

- 库位有 `maxWeight`、`maxVolume`、`abcClass`、`pickSeq`。上架只在 `STORAGE` 里按同批次、空库位、混放规则推荐，不看承重、容积和 ABC。
- `allocate` 的注释写了拣货顺序，排序实际是效期、收货日、库存 id。同效期时不会先出拣货位，也不会按 `pickSeq` 走。
- 物料有 `packQty`（箱规），收货、分配、补货都按基本单位数量处理，没有整箱补货、拆零拣货。

未做的两处：

- 承运商各自的截单时刻。策略只有一个 `cutoffHour`，`groupByCarrier` 只负责分组。
- 波次释放前按未满足的拣货需求补货。现在的补货只看拣货位是否低于 `minStock`，不看已分配但还在存储位的数量。

快消切片要补的模型：

| 对象 | 作用 |
| --- | --- |
| `wms_pick_slot` | 仓库 + 货主 + 物料绑定一个拣货位，以及该拣货位的 min/max |
| 出库单 `orderShape` | 创建时写入 SISQ / SIFQ / SIW / MULTI，策略匹配可复核 |
| `wms_carrier_cutoff` | 仓库 + 承运商 + 每日截单时刻。尾单策略按承运商时钟跑，不再共用一个小时 |

`FMCG` 仓的策略：

- 上架：A 类且拣货位低于 max 时先推荐拣货位，否则推荐存储位；超重或超容积的库位排除。
- 分配：仍是 FEFO，然后 FIFO；同一效期内先拣货位，再按 `pickSeq`。
- 补货：需求量 = max(安全库存缺口, 已分配且不在拣货位的数量)，按箱规向上取整，从存储位补。
- 成波：沿用现有八条策略；截单改读承运商时刻。
- 计件：继续按件。单件订单是否免称重做成策略开关，默认仍称重。

## 大件仓

京东大件（大家电、家居）的作业口径：预约月台卸货，库存落在托盘上，库位按托盘位、承重和堆高收货，出库按单或按整托，叉车执行，序列号绑定送装预约。播种墙不是主路径。人效按托、方、吨，不按件。

本仓库能用的是序列号收发和质检冻结。物料重量体积、库位承重容积只存在主数据里。

未做：容器、托盘位、月台预约、整托分配、叉车任务、送装时段、按托计价。波次播种对大件是错误的默认动作。

`BULKY` 仓的策略：

- 收货生成托盘 LPN，库存行挂在容器上。不带容器的散货仍允许，供小件和历史数据使用。
- 库位增加作业形态：`BIN` 隔板、`FLOOR` 地堆、`BULK` 横梁、`DOCK` 月台。`palletSlots` 与现有承重、容积一起校验。
- 上架按托盘体积和托盘位找位，超限直接拒绝确认。
- 分配：订单数量达到整托时先锁整托，余数再拆。默认不进播种波次，走按单拣货。手工波次仍保留。
- 出库单增加送装窗口和是否安装。发运把这两个字段交给现有 TMS 集成边界，WMS 不排车。
- 月台：`wms_dock`、`wms_appointment`。预约挂 ASN 或出库单，状态为预约、靠台、卸货中、离开。
- 破损：库存状态增加 `DAMAGE`。现有可用量只认 `AVAILABLE`，破损天然不可分配。
- 人效：大件仓的收货、上架、拣货按托盘数计价，件计价留在快消和 `GENERAL`。

## VMI 仓

这里的 VMI 指供应商库存放在本仓，物权仍属供应商，消耗或约定的出库时点才转移。零售寄售和工厂线边取料是同一种账：物理库存一套，物权另一套。

本仓库已经具备：

- 每一行库存带货主。
- 供应商主数据。
- 采购 ASN 收完后，`SrmReceiptClient` 把累计收货量推给 SRM。退货和未收完不推。

货主今天表示存货委托方，供应商表示来货方，两者没有协议，也没有「这行货还是供应商的」这一列。拣货位 Min/Max 是仓内补货，不是向供应商拉动。

`VMI` 要补的账：

| 对象 | 作用 |
| --- | --- |
| `wms_vmi_agreement` | 供应商、货主、仓库、物料、min、max、再订货点、提前期、转移时点 |
| 库存 `ownership` | `CUSTOMER` 或 `VENDOR`。历史行默认 `CUSTOMER`，避免把现有库存改成寄售 |
| 消耗单 | 与销售出库分开。过账时扣物理库存，并按协议写物权转移 |
| 流水 `OWNERSHIP_TRANSFER` | 物权变化单独成行，数量可以不变 |
| 退供出库 | 出库类型 `RTV`，只允许出 `VENDOR` 库存，完成后回传 SRM |

转移时点三种，协议上选一种：

- `RECEIPT`：收货质检放行时转为货主库存。适合到货即买断。
- `SHIP`：销售发运时转移。适合零售寄售。
- `CONSUMPTION`：消耗单过账时转移。适合线边 VMI。

拉动补货：可用寄售量 + 未收完 ASN < 再订货点时生成建议 ASN，数量补到 max，考虑提前期。建议单推 SRM，不在 WMS 里自动收货。供应商可见范围是协议内的库存、在途 ASN 和建议补货，用现有开放接口加供应商过滤，不另做门户。

寄售库龄按 `ownership = VENDOR` 的收货日计算，给 BMS 做负债，不进现有按件操作费。

## 共用设计

### 仓型

`wms_warehouse.profile`：`GENERAL`、`FMCG`、`BULKY`、`VMI`。

策略解析放在一个小的 `WarehouseProfile` 里，返回上架、分配、补货、波次默认、人效口径、物权模式。`AsnService`、`InventoryService`、`ReplenishService`、`WaveStrategyService` 读它。`GENERAL` 的返回值等于今天的硬编码。

一个仓一种主仓型。快消仓里的个别大件 SKU 用物料作业分类 `EACH` / `CASE` / `PALLET` 处理，不把仓库标成混合从而失去默认策略。

### 容器

`wms_lpn`：编码、类型（`PALLET` / `CASE` / `TOTE`）、父容器、库位、状态。

`wms_inventory.lpn_code` 可空。空表示散货，合并规则与现在相同。

库存合并键今天是仓库、库位、货主、物料、批次、`refNo`、状态、效期，表上没有唯一约束，靠 `upsert` 先查后写。加容器或物权时，合并键和唯一索引一起加。否则并发收货会拆出重复行。这一刀单独做，放在快消字段生效之后。

### 作业任务

上架、拣货、波次总拣、播种、补货、盘点任务仍然分表。仓型切片不合并这些表。月台和叉车先用预约和补货/上架任务上的设备字段表达。等 RF 真正要统一领取队列时，再抽作业任务，避免这一轮把执行层重写一遍。

### 库表升级

`schema.sql` 只做 `CREATE TABLE IF NOT EXISTS`。新列同时写入：

- `schema.sql`（新库）
- `schema-h2-upgrade.sql`（本地 H2 文件库）
- `db/mysql-upgrade.sql`（已有 MySQL）

演示数据：`WH01` 保持 `GENERAL`。另加三仓种子只在对应切片的测试里构造，不改 `scripts/smoke.sh` 的现有路径，直到该切片明确要覆盖冒烟。

### 界面

不按仓型复制菜单。仓库档案增加仓型。`FMCG` 突出策略成波和固定拣货位，`BULKY` 突出预约、按单拣货和容器，`VMI` 增加协议、消耗和退供。`GENERAL` 页面与现在相同。

### 测试

沿用现有 JUnit 流程测试的写法，只编译改动的类，用 `org.junit.runner.JUnitCore` 跑相关测试类。不为这个计划做全反应器 Maven 编译。

每个切片的退出标准：

| 切片 | 退出标准 |
| --- | --- |
| 0 账能分 | 跨仓调拨确认后，目标拣货位库存可被 `allocate` 命中。仓内补货和上架测试仍通过 |
| 1 仓型 | 未填 profile 的仓库按 `GENERAL`。现有收货、分配、波次、盘点测试不改断言 |
| 2 死字段 | 超承重或超容积的上架确认被拒绝。同效期库存先分拣货位，再按 `pickSeq`。箱规不改变按件收货的数量 |
| 3 快消 | `FMCG` 仓：固定拣货位被上架和补货优先使用；补货量覆盖已分配缺口；两个承运商按各自截单时刻成波 |
| 4 容器 | 不传 LPN 的收货、上架、分配与切片 2 之后一致。整托收货后库存挂在托盘上，移库带着容器走 |
| 5 大件 | `BULKY` 默认拣货任务不进播种。整托数量一次分配。预约可绑定 ASN。超托盘位拒绝上架。人效按托出数 |
| 6 VMI | 协议内收货写入 `VENDOR`。`CONSUMPTION` 过账后物权变为 `CUSTOMER` 并产生流水。低于再订货点生成建议 ASN。`RTV` 不能发出货主已买断库存 |

## 切片依赖

```text
0 账能分
  -> 1 仓型（GENERAL = 当前行为）
       -> 2 承重 / 容积 / 拣货顺序 / 箱规
            -> 3 快消策略包
            -> 4 容器与唯一索引
                 -> 5 大件（月台、整托、送装、按托人效）
                 -> 6 VMI（协议、物权、消耗、拉动、退供）
```

切片 3 不依赖容器。切片 5 和 6 依赖容器，因为整托和按托消耗都要有 LPN。切片 6 的物权列可以在切片 4 的库存键改造里一起加上，避免连改两次合并键。

## 本轮不做

- 按仓型拆库、拆服务、拆前端工程。
- AGV、电子标签、货到人的设备协议。任务表稳定后再做任务下发。
- 园区车辆调度和运输排程。月台只记录预约和靠台，路径仍在 TMS。
- 供应商门户前端。先做按供应商过滤的开放查询。
- 升级 JDK、Spring Boot，或替换库存引擎。
- 把盘点、上架、拣货、补货合并成一张任务表。

## 检查项

状态：已闭环 / 半成品 / 未做。半成品表示主数据或邻接流程在，当前策略未使用。

### 快消（6 / 2 / 2）

| 项 | 状态 | 依据 |
| --- | --- | --- |
| 单品、多品波次 | 已闭环 | `SISQ` `SIFQ_2` `SIW` `TCQ_2` `SIMO` `SAW` `MIX` `EOW` |
| FEFO 后 FIFO | 已闭环 | `InventoryService.allocate` |
| 箱型与包材扣减 | 已闭环 | 包裹与箱型主数据 |
| 缺货登记 | 已闭环 | 拣货确认可登记缺货 |
| 拣货位 Min/Max | 已闭环 | `ReplenishService.generate` |
| 越库 | 已闭环 | `CrossDockService` |
| 分配使用拣货顺序 | 半成品 | `pickSeq` 已在库位上，分配排序未读 |
| 上架使用承重、容积、ABC | 半成品 | 字段在 `wms_location`，`suggestPutawayLocation` 未读 |
| 承运商各自截单 | 未做 | 只有策略级 `cutoffHour` |
| 按已分配需求补货 | 未做 | 补货只比较拣货位和 `minStock` |

### 大件（2 / 2 / 6）

| 项 | 状态 | 依据 |
| --- | --- | --- |
| 序列号收发 | 已闭环 | 物料 `snControl`，收货登记、发运扫描 |
| 质检冻结 | 已闭环 | 收货进 `QC` 位并冻结，放行后上架 |
| 物料重量体积 | 半成品 | `wms_item.weight/volume` 未参与上架和分配 |
| 库位承重容积 | 半成品 | 字段未参与上架确认 |
| 托盘容器 | 未做 | 无 LPN |
| 托盘位 | 未做 | 库位类型只有暂存、存储、拣货、发货暂存、质检 |
| 月台预约 | 未做 | 无月台、无预约 |
| 整托分配 | 未做 | 分配按数量切片 |
| 送装窗口 | 未做 | 出库只有承运商、运单、地址 |
| 按托人效 | 未做 | `LaborWage` 按件计价 |

### VMI（3 / 0 / 7）

| 项 | 状态 | 依据 |
| --- | --- | --- |
| 库存带货主 | 已闭环 | `wms_inventory.owner_code` |
| 供应商主数据 | 已闭环 | `wms_supplier` |
| 采购收货回传 SRM | 已闭环 | `SrmReceiptClient`，仅已收完的采购入库 |
| 物权 | 未做 | 状态只有 `AVAILABLE` / `FROZEN`，无寄售 |
| VMI 协议 | 未做 | 无 min/max/提前期/转移时点 |
| 消耗过账 | 未做 | 出库即发运，没有消耗单 |
| 向供应商拉动 | 未做 | Min/Max 只补拣货位 |
| 退供 | 未做 | 无 `RTV` 类型约束 |
| 寄售库龄负债 | 未做 | 库龄报表不区分物权 |
| 按供应商查询 | 未做 | 开放快照按仓和货主，不按供应商 |

VMI 清单是 10 项：上表前三项闭环，后七项未做。
